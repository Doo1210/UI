# 万悟平台侧边导航栏规划与功能说明

> 本文记录早期导航讨论。当前目标结构及已实现原型以[2026-10-29 导航结构](导航结构-2026-10-29.md)为准。

> 2026-10-14 修订稿。依据：[平台大改版分析与规划](平台大改版分析与规划.md)和[当前平台截图及侧栏参考](reference/current-platform-2026-10-14/README.md)。本稿定义**目标导航**，不表示所有页面已经实现。主平台使用始终可见的浅色节标题；进入已开通工业平台后，切换为该平台自己的侧栏上下文。

## 一、推荐导航结构

```text
顶部固定
  品牌

首页                                主平台总览与我的工作
资产广场                            独立入口，紧随首页

智能应用                            静态节标题
  专家                              专家列表、创建与管理
  工作流                            工作流列表、设计与管理
  智能体运行时                  组织已开通且角色有权限时显示

能力中心                            静态节标题
  模型中心                          独立菜单；模型接入、配置与供给
  知识中心                          知识库、数据源、检索与治理
  资源库                            工具/连接器、技能与模板

事件中心                            独立入口，页面内承载接入/任务/记录
评测与观测                          独立入口，专家和工作流质量闭环

底部固定
  一行：[API Key 图标] [用量统计图标] [平台运营图标] [管理中心图标]
  仅有一个管理入口时占满右侧两个位置；没有管理入口时前两项各占一半
  用户区：头像｜姓名 角色            [更多]
                 当前组织 [切换]
```

这是**始终可见的静态节标题 + 可点击菜单项**，参考[节标题式侧栏截图](reference/current-platform-2026-10-14/13-section-heading-sidebar-reference.png)。标题只说明分区，不响应点击，也没有展开箭头或折叠状态。资产广场紧随首页，因为它同时服务专家、工作流、模型、工具和解决方案的发现。“智能体运行时”仅在当前组织已开通服务且用户有权限时显示；未开通时从首页高级服务入口进入介绍页。模型中心与资源库是同级、各自可点击的菜单项。工业平台不占主平台侧栏菜单位置；首页使用大卡片展示本体、视觉、时序、设计平台。若屏幕高度不足，顶部品牌和底部管理入口固定，中间菜单独立滚动。

主侧栏宽度为 **180px**；中间业务菜单字体为 **13px**，节标题为 **11px**，并保持紧凑行距。

### 工业平台卡片的两种去向

```text
主平台首页的大卡片
  ├─ 已开通：点击主体 → 平台专属侧边栏与工作台
  ├─ 已开通：点击“查看介绍” → 平台介绍页
  └─ 未开通 / 审批中：点击主体或“查看介绍” → 平台介绍页
                                             └─ 申请开通 / 查看进度
                                    顶部：← 返回主平台 / 平台名称
                                    中部：该平台的专业导航
                                    底部：继续保留适用的全局工具入口
```

这里的“二级导航栏”参考[当前主侧栏](reference/current-platform-2026-10-14/10-main-sidebar-context-entry.png)点击本体智能体后切换到[本体专属侧栏](reference/current-platform-2026-10-14/11-ontology-context-sidebar.png)的交互。它是**替换主侧栏中部菜单的上下文导航**，不是在主侧栏下继续嵌套第三级。刷新、直接打开深链接时也应恢复对应平台侧栏；“返回主平台”回到首页工业平台卡片区域，并保留组织上下文。平台停用或用户失权后，再打开旧链接应进入状态/介绍页，不继续展示专业操作菜单。

截图中的本体专属侧栏已有“本体智能体、知识网络、连接管理、扫描管理、数据视图”等入口，可作为**导航切换方式**的参考；这些栏目是否保留原名应由本体平台的目标产品定义确认。视觉、时序、设计平台各自给出专业菜单，不要求四个平台使用相同菜单模板。

## 二、各导航栏主要内容

### 顶部固定：品牌

顶部只保留品牌。当前组织持续显示在底部用户区的第二行；其旁的独立切换按钮打开向上浮出的组织列表。右侧“三个竖点”按钮打开个人菜单，用户区的其他位置不响应点击。切换组织会返回首页，专家、工作流、知识、资源和工业能力按新组织的上下文展示。

### 首页

侧边栏第一个业务入口，也是登录后的默认首页。顶部显示可用专家数、工作流数及今日、近 7 天、近 30 天的各自使用次数；下一行汇总技能、MCP、插件、知识库数量；下方展示**本体、视觉、时序、设计四张工业子平台卡片**。已开通时点击卡片主体直达工作台，“查看介绍”仍进入详情；未开通时两者均进入介绍页。智能体运行时作为低权重高级入口。当前原型使用演示数字，具体见[新版首页排版规划](首页排版规划-2026-10-29.md)。

### 资产广场

面向“发现与复用”，展示已经审核发布的**专家、工作流、解决方案、工具/模板**，可按工业环节、场景、行业和权限筛选。卡片应写明用途、适用条件、发布者、版本、依赖与使用方式。点击后可试用、安装到本组织、复制为草稿或申请权限。广场中的资产是发布快照；安装后到“专家/工作流/资源库”管理自己的实例或引用。原广场里单智能体、多智能体、对话流的历史资产保留兼容筛选，但不与目标主线平级展示。

### 智能应用

这是平台的主要构建工作区，按“创建专家 → 编排工作流 → 托管高代码智能体”的顺序排列。专家与工作流是主线；智能体运行时作为有需要时才显示的专业入口。发现和安装共享资产通过首页下方的独立广场入口完成。

#### 专家

进入**专家列表**，可搜索、筛选、创建、复制、试运行、评测、发布和停用专家。专家基于改造的 Hermes，面向持续承担某种职责的智能体。详情页建议使用“概览 / 职责与指令 / 工具 / 知识 / 记忆 / 渠道与权限 / 版本 / 运行记录”页签。列表卡片重点展示专家能处理的任务、负责人、适用范围、发布状态和最近运行状况，而不是底层模型或旧智能体类型。专家可以调用资源库工具、知识中心检索能力和已开通工业平台工具，也可以发起工作流。

侧边栏只保留一个“专家”入口；专家任务和协作记录放在专家页面内。旧“单智能体”“多智能体”从默认新建菜单移出，但历史对象可通过兼容入口查看和迁移。

#### 工作流

进入**工作流列表**，承担明确步骤、规则和交付结果的流程构建。列表支持创建、导入、复制、发布、版本管理、搜索和状态筛选。详情页内放画布/节点、入参与出参、调试、版本、执行记录和发布配置。节点可以调用专家、资源库工具、知识检索与工业能力；支持事件触发、定时触发、人工审批、超时和失败处理。历史“对话流”可在兼容区继续运行，适合迁移的对话步骤逐步融入工作流，避免继续作为一级创建类型展示。

#### 智能体运行时

这个菜单承接现有[智能体运行时](reference/current-platform-2026-10-14/12-high-code-agent-runtime.png)的真实职责：**部署和管理托管高代码智能体，提供安全稳定的容器化运行环境**。它是高代码智能体的交付与托管入口，不是所有专家/工作流运行记录的汇总页。用户可通过 YAML 导入或托管高代码智能体，查看运行实例、部署版本、状态、Pod、自动扩缩容、访问入口和运行日志。需要代码部署的开发者和运维人员可见；仅使用专家/工作流的普通用户不必看到。

页面内保持两个主要页签：

- **运行实例**：部署、更新、启停、扩缩容、查看访问地址、健康状态和容器日志。实例关联镜像版本、组织与负责人。
- **镜像仓库**：管理 Harbor 中供托管实例使用的镜像、版本、推拉与安全扫描。它是高代码交付链的一部分，不进入通用资源库。

如果一个托管高代码智能体需要被专家或工作流调用，它对外发布的 API/工具再登记到“资源库 → 工具与连接器”。**托管实例与可调用工具是两个关联对象**，不要把整个容器实例当作普通工具卡片。原有“智能体运行时”路由和分享链接应兼容跳转到新菜单。

### 能力中心

这是专家和工作流依赖的基础能力。模型、知识、工具分别有独立的资产生命周期，三者在侧边栏同级展示。

#### 模型中心

独立管理语言模型、嵌入模型、重排模型和视觉模型的接入、能力信息、服务端点、可用范围、配额、成本与健康状态。专家和工作流从这里选择模型，但模型的供给、发布、授权和停用在模型中心完成。模型对比、调用测试和版本管理可做成模型中心内部页签，不塞回资源库。

#### 知识中心

基于改造的 WeKnora，管理全平台可检索、可引用的知识。它与“本体平台”边界不同：知识中心主要管理文档、FAQ、规程和检索索引；本体平台主要管理设备、产线、工厂等结构化工业对象及其关系。

- **知识库（页面内）**：创建与维护知识库，管理文档/目录、标签、版本、访问权限、解析与索引状态、发布及回滚。专家或工作流在这里选定知识库及检索策略。
- **数据源（页面内）**：配置文件上传、外部系统同步与定时更新，查看同步状态、失败重试和数据来源。工业知识可记录工厂、设备、工艺、有效时间等元数据。
- **检索调试（页面内）**：输入问题或检索条件，查看召回片段、引用出处、权限过滤、排序效果和回答质量，便于知识管理员在交给专家使用前验证。

知识审核、纠错和审计可先作为知识库详情页页签；当治理工作形成独立队列时，在知识中心页面内增加“知识治理”工作区。原资源库“知识”入口跳转到知识中心对应对象，不保留双重上传后台。

#### 资源库

面向“接入、配置和授权可复用能力”，由专家和工作流共同引用。与广场的发现/安装职能分开。每项资源都应展示所有者、协议、版本、可用范围、健康状态、调用限制和引用情况。

- **技能（页面内 Tab）**：管理专家和工作流可复用的技能及其版本、依赖和发布状态。
- **MCP（页面内 Tab）**：管理 MCP 服务及其开放工具、接入配置、授权和可用状态。
- **插件（页面内 Tab）**：管理可调用的插件工具、输入输出、测试及发布配置。
- **连接器（页面内 Tab）**：管理数据库与 MES/ERP/IoT 等系统连接、凭证引用和连接状态。工业平台开放的能力按接入形式归入相应 Tab。模型和知识库在各自中心管理，记忆属于专家配置，安全护栏属于治理策略。

### 事件中心

作为一个**独立、直接进入的侧边栏菜单**，承接已有“事件接入 + 事件任务”链路，也是工业平台事件进入主平台的统一入口。后续不再把事件接入、任务拆成多个侧边栏菜单；在同一页面内用页签或局部导航组织。截图中的“事件引擎”即这里的能力，不再出现第二套事件后台，也不需要为一个菜单单设“工业协同”分组。

- **事件接入（页面内）**：管理 WebHook、定时器、Kafka 等触发源，后续接入视觉告警、时序异常、本体规则命中、设计审查结果。展示事件 schema、测试、启停、调用次数和接入健康状态。
- **事件任务（页面内）**：配置事件匹配、规则、去重、路由、关联专家/工作流、人工处理、重试和失败处置。现有任务配置可延续，逐步扩展工业对象上下文。
- **执行记录（页面内）**：按事件查看处理过程、关联任务、调用的专家/工作流、结果回写与失败原因；可跳转到“评测与观测”的完整 Trace。

### 评测与观测

面向专家和工作流的质量闭环。日常查看某个对象的结果，应从其详情页直接进入，并自动带入对象和版本；这里是跨对象的统一工作区。

- **评测（页面内）**：测试集、批量运行、人工/自动评分、版本对比、回归测试和发布门槛。既评估专家回答，也评估工作流执行结果。
- **观测（页面内）**：跨专家/工作流查看会话、任务、Trace、模型/工具/知识/工业 API 调用、耗时、成本、失败、重试和反馈；异常样本可加入评测集。

普通使用者可以只看自己的任务详情；开发者和运营者根据权限看到本组织或全平台视图。这里关注专家/工作流的回答与任务质量、调用链、工具和模型表现；高代码容器的 Pod、镜像和扩缩容仍在“智能体运行时”页面。

### 底部固定入口

- 固定区上方是**四个独立的白底圆角矩形按钮**，高 30px，彼此间隔 2px，使用很浅的蓝色边框；下方用户按钮高 36px，与上方间隔 4px。四个入口默认从左到右为 API Key 管理、用量统计、平台运营、管理中心；鼠标悬停或键盘聚焦时立即显示名称提示。原型用户菜单提供“有无平台运营”“有无管理中心”两个独立开关；只显示其中一个时，它占满右侧两个位置并显示短标签；两个都隐藏时前两项各占一半。下方用户按钮悬停时只调整边框与阴影，不上移；上方四个入口保持固定，仅显示淡蓝底与名称提示。业务菜单与固定区的交接处仍使用毛玻璃过渡，不加独立横线。
- **用量统计**：查看专家、工作流、模型、知识检索、工具与工业能力的调用量、成功率、耗时和消耗；按本人/组织/平台权限显示相应数据范围。与“观测”相比，这里偏计量和总览。
- **API Key 管理**：创建、轮换、禁用本人或获授权范围内的密钥，查看用途、最近使用和审计；密钥明文仅创建时展示。
- **平台运营**：仅运营人员和系统管理员可见，包含资产审核、广场治理、运营看板及必要的内容处置。普通用户不显示。
- **管理中心**：组织与成员、角色权限、工业平台开通审批/配置、平台设置、凭证与安全策略、审计日志。组织管理员只看到本组织可操作项，系统管理员看到平台项。工业平台详情页的“申请开通”是用户入口，此处是管理审批与配置入口。
- **个人账户 / 帮助**：位于下方独立的圆角长方形中。用户卡片高 48px，头像右侧第一行显示姓名与角色，第二行将当前组织名称与用户提供的双向箭头合成一个按钮。长组织名截断显示，悬停可查看完整名称；点击组织名或箭头都会向上打开组织选择浮窗。最右侧三个竖点独立打开个人菜单，卡片其余位置没有点击行为。与上方入口保持 4px 间距。

## 三、旧菜单到新菜单的去向

| 当前入口 | 建议去向 |
|---|---|
| UniBot | 从目标导航和首页移除；历史入口按迁移计划下线 |
| 专家 Beta | 升级为核心“专家”入口 |
| 智能体开发 | 拆为“专家”和“工作流”两个正式入口；旧类型进兼容区 |
| 资产广场 | 从“智能应用”移至首页下方，成为独立发现入口；默认聚焦专家、工作流、解决方案及可复用资源 |
| 资源库-插件/MCP | 合入“工具与连接器”，通过协议类型筛选 |
| 资源库-模型 | 迁至独立“模型中心”菜单，不继续作为资源库页签 |
| 资源库-知识 | 迁至“知识中心”，资源库只保留引用关系 |
| 资源库-记忆/提示词/安全护栏 | 分别进入专家配置、技能与模板、管理中心策略 |
| 事件接入/事件任务 | 合为侧边栏单项“事件中心”；页面内保留接入、任务和执行记录 |
| 工业引擎-事件引擎 | 指向事件中心，不再有重复平台入口 |
| 工业引擎-工具插件 | 归入资源库“工具与连接器” |
| 工业引擎-本体/视觉/时序/设计 | 首页卡片承载；已开通卡片主体直达专属侧栏，独立“查看介绍”入口仍进入介绍页 |
| 智能体运行时/镜像仓库 | 归入“智能应用 → 智能体运行时”，页面内保留“运行实例 / 镜像仓库”页签 |
| 统计看板/API Key/运营看板/管理中心 | 归入底部固定区；运营看板在“平台运营”内 |

## 四、显示与交互规则

1. **菜单可见、页面可进、数据可看、操作可做**分开校验。前端隐藏只改善体验，后端仍按组织、角色、对象与工业平台开通状态校验。
2. **首页工业平台大卡片对所有用户可见**；未开通的平台保留详情与申请入口，不提供专业工作台操作。待审批/配置中在详情页说明状态；到期/停用后保留必要的历史记录入口，禁用新调用。
3. 节标题不响应点击，其下菜单始终显示。专家和工作流直接到列表，不为“列表”再创建额外一层；详情操作放页面内。
4. 资产广场与资源库互相跳转，但页面明确标识“已发布的共享资产”与“我/本组织可管理的资源”。
5. 全局搜索可搜索专家、工作流、知识库、工具、智能体运行时实例和工业对象；结果按权限过滤，避免用户必须猜测入口。
6. 低频管理功能放底部并按角色过滤。管理员在平台运营/管理中心下有多个可见页面时展示二级菜单；只有一个可见页面时可直接进入。
7. 已开通工业平台的专属侧栏保留顶部组织信息和适用的底部全局入口，中部顶部显示“左箭头 + 当前子平台名称”的返回按钮，下方直接显示专业菜单，移除重复的平台图标与名称；平台内部菜单由各平台的真实业务对象决定。未开通时只显示介绍页，不切换侧栏。

## 五、建议先做的导航验收

- 普通用户 10 秒内能找到“创建专家、创建工作流、查知识、申请视觉平台”，并能直接找到独立的模型中心菜单。
- 已开通视觉平台用户点击卡片主体进入专属侧栏、点击“查看介绍”进入介绍页；未开通用户从卡片进入介绍页。视觉事件可进入主平台的事件中心，再进入关联工作流执行记录。
- 未开通组织看不到视觉工具和工作台，直接访问旧链接/API 也不能越权使用。
- 旧单/多智能体及对话流仍可被其拥有者通过兼容入口查看和运行，原分享链接不中断。
- 仅使用专家/工作流的普通用户不看到 Pod、镜像、组织管理等入口；有权限的开发/运维人员在智能应用分组下找到智能体运行时。
