## 页面结构

### 应用概况三类数据（最新）

概况主体分为“智能应用 / 使用次数 / Token消耗”三组：智能应用展示专家和工作流数量；使用次数展示专家调用和工作流执行；Token消耗展示消耗总量。使用次数和 Token 消耗分别提供今日、近7日、近30日、近180日的独立文字筛选，均默认近30日，时间单位统一为“日”。两组筛选互不影响，角色统计范围同时作用于三组及可用资源。

Token 使用模拟总量，按范围展示 K / M 紧凑数字，悬停数字可查看完整 Tokens 数值；尚未对接真实用量统计或计费服务。桌面三列对齐，小屏按组堆叠，页面三大区块仍保持 4:1:3 比例。

## 统计口径与实现边界

### 首页统计范围与高级功能布局

应用概况与可用资源使用同一统计范围：系统管理员可切换全平台 / 个人，组织管理员可切换全组织 / 个人；普通用户和运营角色仅显示个人，不显示切换按钮。切换同时更新对象数量、分时段使用次数和四类资源数量。角色或组织变化时重置到该角色默认范围；数字均为原型模拟，未接入实际权限和统计服务。工业引擎开通状态独立按当前组织显示。高级功能不再包含在统计容器内，拆为资源区与工业引擎之间的独立白色圆角矩形，保持内容高度。桌面弹性网格按统计容器 / 高级功能 / 工业引擎三行分配空间。

### 工业引擎介绍页

四个子平台使用统一介绍页模板：顶部固定 Banner（返回首页、平台图标与名称、状态、申请或进入操作）、六四分栏的平台介绍及可放大预览、三项能力、专家与工作流协同、两个业务场景及开通说明。介绍页内容允许滚动，顶部 Banner 始终可见，移除首屏及底部重复操作条；窄屏 Banner 分两行，并为内容预留顶部空间。保留主侧栏；已开通时点击“进入平台”才切换到专属导航。

预览图使用可缩放 SVG 与 HTML 构建，全部标为模拟界面：本体展示对象关系，视觉展示检测画面与异常框，时序展示温度曲线与异常时间窗，设计展示组件图纸与审查版本。图中数字、对象和图纸均为原型示例，协同流程标记为拟议方案，不作为生产能力证明。

未开通时通过申请弹窗填写申请人、联系方式和用途，组织预填且只读。提交后显示审批中及申请详情，可关闭后重新查看；信息按组织与平台保存在页面会话中，刷新后重置。仅系统管理员可在待审批状态执行“模拟审批通过”，通过后显示“进入平台”。正式服务、审批后台、通知发送和价格均未接入。

### 高级功能介绍页

三个介绍页共享顶部固定 Banner（返回首页、功能图标名称、状态与开始操作），正文采用“用途与适用人员 + 交互示例”“三项主要用途”“三步使用路径”“典型场景与使用前说明”的轻量布局，不使用工业引擎的对象关系与业务协同模板。

- 智能体运行时：展示模拟实例与部署日志；未开通可填写用途、申请人和联系方式，审批中可查看详情，系统管理员可模拟审批通过；已开通且有权限才可进入运行时工作区。申请按组织在当前会话保存。
- 软件开发套件：Python / JavaScript 切换展示伪代码请求结构，明确标记不可直接运行；顶部“查看开发指南”进入已有软件开发套件工作区。不提供虚构的包安装命令、下载链接或生产接口。
- 低代码 UI：示例界面可选择多条工作流，点击“模拟提交”只显示模拟结果；取消所有关联后按钮禁用。顶部“进入 UI 工作台”打开已有多工作流绑定工作区。

软件开发套件与低代码 UI 不新增审批或收费限制；侧栏现有入口仍可直接进入工作区。介绍页里的图文、数据和操作均为原型示例。

- 专家数、工作流数：建议统计当前组织下用户有权使用的已发布对象；草稿另在管理列表展示。
- 专家调用次数和工作流执行次数分别统计。工作流内部调用专家可同时计入各自指标，不把两项简单相加成“总使用次数”。低代码 UI 或事件触发的工作流执行也应纳入工作流指标。
- 资源数量：按当前组织的可用范围统计；知识库虽显示在此处，管理入口仍在知识中心。
- 原型目前使用分组织缩放的演示数字，并在页面注明“原型示例数据”；尚未接入生产统计 API。平台开通状态也是当前会话中的演示状态。

正式接入时先确定对象可用范围、调用成功/失败计数、时间范围边界和去重规则。详情入口应带上当前组织与相应筛选条件。
