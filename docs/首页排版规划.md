# 万悟平台首页排版规划

> 本文是早期设计稿。当前已实现的首页结构以[2026-10-29 版本](首页排版规划-2026-10-29.md)为准。

> 2026-10-14 设计稿。与[侧边导航栏规划](侧边导航栏规划与功能说明.md)配套。目标是让用户进入平台后立即知道“现在能做什么、手头要处理什么、有哪些工业平台可用”，并从首页大卡片进入本体、视觉、时序、设计平台。

## 1. 首页承担的任务

首页服务两类人：初次接触平台的人需要理解主平台与工业平台的关系；已在平台工作的用户需要继续专家/工作流任务、处理异常并进入已开通的工业平台。页面只承担**认识、选择、继续工作**三个动作，具体配置留在各工作区。

主平台的一句话定位建议写为：**“让专家与工作流连接工业知识、数据和现场任务。”** 它比抽象的“AI 平台”更能解释后续的卡片与任务区。主要动作固定为“创建专家”“创建工作流”；已存在任务的用户可从右侧继续工作。资产广场通过侧边栏的独立入口进入，不重复做一排广场卡片。

## 2. 桌面端总体布局

建议以内容区最大宽度 1440px、左右留白 32–40px、12 列栅格为基准。首页分三屏内的层次：**平台定位与工作状态 → 工业平台大卡片 → 最近工作与异常**。卡片区是首页最强的视觉识别点，使用真实业务信息而非装饰性插画。

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 首页                                             当前组织 / 帮助入口           │
├───────────────────────────────────────┬──────────────────────────────────────┤
│ 主平台定位                            │ 我的工作                             │
│ 让专家与工作流连接工业知识、数据和现场任务 │ 待处理 3  ·  运行中 5  ·  异常 1      │
│ [创建专家]  [创建工作流]              │ 最近任务：设备异常处置 → 继续        │
├───────────────────────────────────────┴──────────────────────────────────────┤
│ 工业平台                         已开通 2 / 4     [查看全部状态]             │
│ ┌───────────────────────────────┐ ┌───────────────────────────────┐        │
│ │ 本体平台              已开通   │ │ 视觉平台              未开通   │        │
│ │ 设备、产线与业务对象的关系    │ │ 从图像识别结果进入处置流程    │        │
│ │ 对象关系 / 规则 / 数据视图    │ │ 设备 / 检测 / 告警           │        │
│ │                  [进入平台 →] │ │              [了解并申请 →]  │        │
│ └───────────────────────────────┘ └───────────────────────────────┘        │
│ ┌───────────────────────────────┐ ┌───────────────────────────────┐        │
│ │ 时序平台              已开通   │ │ 设计平台              审批中   │        │
│ │ 查看设备趋势与异常            │ │ 连接设计对象、版本与审查任务  │        │
│ │ 指标 / 时间窗 / 异常          │ │ 设计对象 / 版本 / 审查        │        │
│ │                  [进入平台 →] │ │              [查看进度 →]    │        │
│ └───────────────────────────────┘ └───────────────────────────────┘        │
├──────────────────────────────────────────────┬───────────────────────────────┤
│ 继续工作                                     │ 需要关注                      │
│ 最近专家、工作流和任务                       │ 失败任务 / 事件 / 知识更新    │
└──────────────────────────────────────────────┴───────────────────────────────┘
```

### 顶部：平台定位 + 我的工作

左侧约占 7 列：标题、简短说明、两个主动作。标题不宜超过两行，不加入大段营销文案；有真实典型场景时，可以在标题下用一行说明，例如“从视觉告警到专家研判，再到工作流处置”。右侧约占 5 列：我的待办、运行中、异常三个可点击数字，以及一条最近任务。数字只显示当前用户有权查看的范围。新用户没有任务时，右侧改为“从一个示例开始”，提供具体专家/工作流样例，不显示 0/0/0 的空看板。

### 中段：四张工业平台大卡片

卡片按 **2 列 × 2 行** 排列，每张桌面端约 520–650px 宽、190–230px 高，面积足以容纳名称、用途、状态与动作。排序优先依据客户业务的重要性；没有确定优先级前沿用“本体、视觉、时序、设计”。每张卡片保持相同结构：

1. 左上：平台图标/示意符号与名称；右上：清楚的状态标签。
2. 中间：一句“能解决什么问题”的说明，最多两行。再列 2–3 个能被用户识别的业务对象或能力词。
3. 右下：唯一主动作。整个卡片可点击，并与按钮去向一致，避免卡片跳工作台而按钮跳介绍页。

文案可从这些方向起草，但上线前需由各平台负责人核对：

- **本体平台**：统一设备、产线与业务对象关系；示例词“对象关系 / 规则 / 数据视图”。
- **视觉平台**：把图像检测结果转为可处理的告警和任务；示例词“设备 / 检测 / 告警”。
- **时序平台**：查看设备指标趋势、异常与时间窗数据；示例词“测点 / 趋势 / 异常”。
- **设计平台**：连接设计对象、版本和审查流程；这是待核定文案，具体能力以设计平台实际产品为准。

卡片视觉建议沿用现有平台的蓝色体系，但通过**工业图纸式的细线关系图、时序曲线、检测框等轻量线形符号**区分平台；信息层仍使用统一的白底/浅底与排版，不给四张卡片分别使用强烈渐变。工业线形只辅助识别，不能覆盖文字和状态。状态标签与动作文案必须同时表达状态，不能只靠颜色。

### 底部：继续工作 + 需要关注

左侧占 8 列，列出最近使用的专家、工作流及最近任务，显示名称、类型、更新时间和“继续”入口，最多 5 条。右侧占 4 列，放失败任务、待人工处理的事件、知识源同步失败等需要行动的提醒，按严重程度排序。每条通知应直接跳到可处理页面；普通更新不宜与失败告警使用同样视觉权重。若没有提醒，显示最近可用能力或“开始创建”的动作，不留一个空白卡片。

事件中心是主侧栏独立菜单，首页只显示与当前用户有关的事件提醒和数量，不再额外放一个“事件引擎”大卡片，避免与四个工业平台并列时产生重复概念。

## 3. 卡片状态与点击行为

| 状态 | 卡片主动作 | 点击后页面 |
|---|---|---|
| 未开通 | 了解并申请 | 平台介绍页：价值、能力、开通条件与申请流程 |
| 待审批 | 查看进度 | 申请详情及预计下一步，不重复提交 |
| 配置中 | 查看配置状态 | 接入检查、缺失配置与负责人 |
| 已开通且有权限 | 进入平台 | 切换为该工业平台的专属侧栏与工作台 |
| 已开通但当前用户无权限 | 了解权限 | 平台介绍/权限说明，可申请使用权限 |
| 暂停或到期 | 查看状态 | 状态、历史数据可读范围及恢复途径 |

**首页卡片始终可见**，这样未开通用户也能认识平台；但各状态都要指向有效页面。开通状态不能只从前端缓存推断，进入专业平台时仍需服务端校验组织、用户和能力就绪情况。

已开通平台点击后的侧栏参考[本体专属侧栏截图](reference/current-platform-2026-10-14/11-ontology-context-sidebar.png)：保持品牌和组织上下文，中部切换为“返回主平台 + 平台名 + 专业菜单”，底部保留适用的全局工具入口。返回主平台后，回到首页工业平台卡片区域；浏览器后退/刷新/直接打开深链接都应保持导航上下文一致。

## 4. 布局比例与响应式

- **宽屏（≥1440px）**：顶部 7/5 分栏；工业卡片 2×2；底部 8/4 分栏。内容最大宽度 1440px，避免在 2K 屏上把卡片拉得过宽。
- **中屏（约 900–1439px）**：顶部可保持 7/5 或改 6/6；工业卡片仍 2 列，减少水平内边距，卡片文字最多两行。
- **窄屏（<900px）**：顶部“我的工作”移到主标题下方；工业卡片改 1 列；底部两栏合并。侧边栏变抽屉，工业平台专属侧栏仍通过“返回主平台”切换。
- **手机（<600px）**：优先显示标题、两个主动作及卡片状态；卡片能力词可收起，保持名称、说明和动作清晰。不要使用横向滚动的四卡走马灯，否则用户容易漏看未露出的平台。

## 5. 视觉与文字层级

这是工业工作平台，首页建议呈现“**清楚的工作台 + 有辨识度的工业能力区**”。设计基调延续现有蓝白界面，正文强调可读性；工业卡片采用低对比线稿表现对象连接、波形或检测区域，而非通用机器人插画。建议的设计令牌在制作原型时统一验证：主蓝 `#2563EB`、工业青 `#0EA5B7`、深灰 `#1F2937`、浅底 `#F5F7FB`、分隔线 `#DCE3EC`、风险提示 `#B45309`。中文正文优先使用系统无衬线字体，指标数字可使用清晰的等宽或数字字体；大标题 28–32px、区块标题 20–22px、正文 14–16px，状态 12–13px。

页面的**唯一强视觉区**是工业平台卡片矩阵；顶部行动区和底部任务列表保持克制。交互动效只用于卡片悬停、展开与侧栏上下文切换，持续时间约 150–220ms；键盘焦点必须明显，并尊重减少动画偏好。

## 6. 首页与其他页面的边界

- 首页展示“已发布专家数、运行任务、异常提醒”的摘要，不承担完整统计分析；查看明细跳“用量统计”或“评测与观测”。
- 首页工业卡片是入口，平台介绍页回答“值不值得开通、怎样开通”，专业工作台处理真正的工业对象和任务。
- 首页最近工作用于继续操作，不重复专家/工作流列表的全部筛选和管理能力。
- 首页展示与当前组织有关的工业能力状态，不把一个组织的开通状态展示给另一个组织。

## 7. 设计验收

1. 新用户进入首页 10 秒内能说出主平台的主要用途，并找到创建专家、创建工作流及四个工业平台入口。
2. 未开通与已开通用户点击同一平台卡片，分别稳定进入介绍页和专业平台侧栏；待审批、配置中、无权限状态也有明确去向。
3. 已开通平台的专属侧栏能够通过首页卡片、浏览器后退、刷新和深链接正确恢复；返回主平台不丢组织上下文。
4. 在常见 1366×768 和 1920×1080 桌面窗口中，首屏能看到至少一排工业平台卡片及其状态；窄屏不出现横向溢出。
5. 首页任务、事件和工业状态遵守组织及用户权限；卡片、按钮、状态文案可键盘访问并且语义一致。
